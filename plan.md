# План исправления WorkTime

Основан на аудите всех веток и прогоне release-подобной сборки на `oneplus-13s-2`.
Принцип: **не переписывать с нуля**. Данные, калькулятор и бэкап в `main` надёжные
и покрыты тестами — их оставляем. Слой UI заменяем по экранам.

## Диагноз

- Идея и слой данных в порядке. Проблема в UI-слое: он переусложнён, а тесты закрепляют
  его пиксельную геометрию, поэтому правки ломают соседнее (8 коммитов «restore/revert
  summary sheet», 144 коммита `ui:`/`fix:`).
- Суммы расходятся: полоска 34 388 ₽, отчёт 34 387,5 ₽, ячейка 2 713 при реальных 2 712,5.
  Оплата хранится в micros и нигде не округляется до копеек.
- Главный экран: сетка с фиксированной высотой строк, ~40% экрана пусто, линии как в Excel.
- Годовой отчёт: 12 строк на весь экран, 11 пустых.
- Формат времени смешан («12» в ячейке, «98:15 h» в сводке).
- Месячный отчёт на `BottomSheetScaffold` со скрытым состоянием — главный источник
  «возвращающихся» багов.
- Лаг (по коду): тяжёлая работа в каждой из 42 ячеек × 3 страницы пейджера
  (`DateTimeFormatter`, `SalaryCalculator` в `runCatching`, 8 `stringResource`),
  нестабильный `CalendarUiState` в сетке, два источника правды для месяца
  (пейджер на 24 001 страницу с самописным `Animatable` + `ViewModel.visibleMonth`).

## Этап 1 — корректность денег и ставок

- [x] Округлять оплату каждой записи до копеек; итог месяца/года = сумма округлённых записей
      (`SalaryCalculator.roundToCents`, тесты добавлены).
- [x] Единый формат денег во всех местах: целое без десятичных, иначе всегда 2 знака
      (`formatAmountMicros` в ячейке, полоске, отчётах, виджете).
- [x] Миграция Room не нужна — схема не менялась.
- [ ] Таблица периодов ставок — **отложено**: требует новой таблицы, backup v3 и отмены;
      текущая массовая смена ставки корректна для существующих записей. Вернёмся после Этапа 3.
- [x] Массовая смена ставки — в диалоге подтверждения показывается число затронутых записей;
      при нуле кнопка отключена; Undo уже было.
- [x] Лимит размера импорта уже был (4 МБ); вместо файла-автобэкапа (недоступен без root)
      сделана отмена импорта — снекбар «Отменить» восстанавливает записи и настройки.
- [x] Ставка по умолчанию не задана — в настройках вместо «0» показывается «Задать».

## Этап 2 — архитектура UI

- [x] `CalendarMonthUi` (42 готовых `@Immutable` `DayCellUi`) строится один раз на страницу
      через `remember` (`buildCalendarMonthUi`, покрыто JVM-тестами); ячейка ничего не считает.
- [x] Пейджер: 1561 страница (1970–2100) вместо 24 001, `animateScrollToPage`/`scrollToPage`,
      единственный источник месяца — `visibleMonth` во ViewModel; самописный `Animatable` удалён.
- [x] Месячный отчёт — карточка под календарём (bottom sheet, SupportingPane и связанные
      тесты удалены); нажатие открывает годовой отчёт. Отдельный экран деталей не нужен.
- [x] Редактор дня: 4 обычных `OutlinedTextField` (премия и штраф в одной строке),
      `evaluateDayEditor` с валидацией, покрытой JVM-тестами; клавиатура при открытии не показывается,
      IME Next по цепочке полей, Done в «Штрафе» сохраняет. Пружинный «переезжающий» ввод удалён.
