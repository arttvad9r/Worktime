# Исследование RuStore для WorkTime

Дата проверки: 2026-09-04.

Цель: подготовить первую карточку WorkTime в RuStore на основе актуальных правил площадки и того, как оформлены заметные приложения из той же предметной области.

## Что делают заметные приложения категории

### Календарь рабочих смен

RuStore: `com.lrhsoft.shiftercalendar`

- 100 тыс.+ скачиваний, рейтинг 4,8, возраст 0+;
- основная категория — `Полезные инструменты`;
- используются теги `Личные финансы`, `Работа`, `Календарь`;
- название сразу объясняет основной сценарий: календарь рабочих смен.

### График смен — Simple Shift

RuStore: `com.groviapp.shiftcalendar`

- 90 тыс.+ скачиваний, рейтинг 4,8, около 1,4 тыс. оценок;
- 7 скриншотов;
- категория `Полезные инструменты`, теги `Работа`, `Календарь`;
- сводка RuStore по отзывам отдельно отмечает удобный интерфейс, визуализацию графика, цветовое решение, дизайн и скорость работы.

### Табель учета рабочего времени

RuStore: `com.dev.workshiftcalendar`

- 20 тыс.+ скачиваний;
- 5 скриншотов;
- возраст 0+;
- `Полезные инструменты` + теги `Личные финансы`, `Работа`, `Календарь`, `Калькуляторы`, `Личные помощники`;
- описание сразу обещает два ключевых сценария: фиксацию рабочего времени и расчёт зарплаты в календаре;
- в свежих отзывах повторяется претензия к большому количеству рекламы. Для WorkTime отсутствие рекламы — реальное и полезное отличие, которое можно указывать без сравнительных формулировок.

### Табель учета рабочего времени

- основная категория `Бизнес-сервисы`, теги `Работа`, `Калькуляторы`, `Личные помощники`.

### WorkTime Plus График смен и учет рабочего времени

RuStore: `wtdevteam.worktimeplus`

- 7 тыс.+ скачиваний;
- возраст 0+;
- категория `Полезные инструменты`;
- функциональное длинное название дополнительно показывает, что одно слово `WorkTime` само по себе недостаточно хорошо объясняет назначение и может пересекаться с существующими приложениями.

## Выводы для WorkTime

1. Название должно начинаться с бренда, но сразу раскрывать задачу. Поэтому подготовлено `WorkTime — учёт смен и часов`, а не просто `WorkTime`.
2. Для личного календаря смен наиболее устойчивый выбор — `Полезные инструменты`, а не `Бизнес-сервисы`: приложение не является корпоративной системой работодателя.
3. Возрастная маркировка `0+` соответствует и содержанию WorkTime, и большинству прямых аналогов.
4. Заметные аналоги обычно используют 5–7 кадров. Для WorkTime итоговая серия состоит из 6 полноценных рекламных композиций 1080×1920: Hero-календарь, запись смены, годовые итоги, темы, local-first/privacy и экспорт.
5. Первый кадр показывает основной сценарий и объясняет приложение без чтения описания.
6. Полезные отличия WorkTime, подтверждённые сборкой: отсутствие рекламы, отсутствие аккаунта, основные функции без интернета, локальное хранение данных, светлая/тёмная/системная темы, годовые итоги, экспорт и импорт.
7. Галерея не копирует оформление конкурентов и не использует агрессивное ASO: крупная типографика, настоящий UI, минимум текста и единая визуальная система.

## Актуальные требования RuStore, учтённые в подготовке

- название — до 30 символов и должно быть уникальным;
- короткое описание — до 80 символов;
- подробное описание — до 4000 символов;
- до 5 поисковых тегов только из списка RuStore;
- хотя бы один контакт разработчика обязателен;
- APK и AAB поддерживаются; APK должен быть подписан цифровым сертификатом;
- для обновлений пакет и подпись должны совпадать с предыдущей версией, а номер версии увеличиваться;
- для телефона требуется не менее 3 скриншотов, максимум 10;
- изображения должны показывать актуальную функциональность, не содержать Android UI/чужой интерфейс и соответствовать пропорции 9:16 или 16:9;
- финальные WorkTime-карточки имеют 1080×1920 и меньше 3 МБ каждая;
- иконка имеет 512×512, квадратная, с заполненным фоном, меньше 1 МБ и основана на реальной установленной иконке WorkTime;
- для первой публикации выбран ручной режим, чтобы после модерации отдельно проверить финальную карточку;
- форма безопасности данных должна заполняться по точной сборке и с учётом пользовательских данных, а не только Android permissions;
- соглашение RuStore требует предоставить пользователям сведения о разработчике, политику конфиденциальности и пользовательское соглашение.

## Подпись после утраты ключа 0.1.0

Приватный ключ, которым был подписан прямой GitHub-релиз `0.1.0`, утрачен. Его невозможно восстановить из публичного APK или отпечатка сертификата.

RuStore прямо указывает, что Android сравнивает цифровые отпечатки сертификатов APK и не разрешает обычное обновление, если подписи различаются. RuStore также рекомендует использовать одну и ту же подпись во всех магазинах; при утрате ключа для уже опубликованного в RuStore приложения замену можно проводить через поддержку магазина.

Для WorkTime ситуация проще: в RuStore приложение ещё не публиковалось, поэтому существующей RuStore signing identity нет. Первая версия RuStore может быть подписана новым ключом без процедуры замены сертификата в поддержке.

Принято решение:

- создать новый developer-controlled production key локально;
- использовать его для первой RuStore-версии `0.2.0`;
- использовать **тот же новый ключ** для всех дальнейших RuStore и прямых GitHub APK, чтобы с `0.2.0` снова была единая update identity;
- не считать число оставшихся установок `0.1.0` гарантированно нулевым; для любой такой установки действует миграция JSON export → uninstall → new install → JSON import;
- тестовые `.debug` сборки остаются отдельным application id и не определяют production signing identity.

В репозитории добавлен `scripts/init_production_signing_key.sh`. Он предназначен только для запуска на доверенном локальном компьютере: создаёт новый RSA 4096 keystore вне репозитория, экспортирует публичный сертификат и обновляет только публичный fingerprint в `release/production-signing-cert-sha256.txt`.

## Почему APK, а не AAB

Для первой публикации WorkTime оставлен путь через подписанный APK:

- размер приложения мал, поэтому выигрыш split-доставки сейчас невелик;
- APK оставляет приватный ключ полностью под контролем владельца проекта;
- RuStore поддерживает такой путь и требует стандартно подписанный APK;
- после утраты старого ключа важнее сначала закрепить новую единую signing identity для `0.2.0+`, чем одновременно вводить дополнительную инфраструктуру AAB/upload key.

Это не ограничивает будущий переход на AAB. При переходе нужно отдельно настроить ключ загрузки и подпись приложения согласно актуальной инструкции RuStore.

## Privacy/legal вывод

Само приложение local-first: рабочие записи не отправляются разработчику автоматически. Однако выбранный в будущем канал поддержки может создавать отдельный developer-side поток персональных данных, если пользователь добровольно направит e-mail, имя, текст обращения или вложения. Поэтому до публичного запуска поддержки нужно проверить фактического провайдера/место хранения, применимые требования к локализации и трансграничной передаче и необходимость уведомления Роскомнадзора.
